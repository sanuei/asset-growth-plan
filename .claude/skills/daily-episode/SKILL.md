# 每日自动出片

每天固定发布一支视频。定时任务每天早上 9:00（日本时间）启动，视频定在 **台湾时间 20:00（日本时间 21:00）** 公开。

项目目录：`/Users/yangshangwei/Desktop/從零開始的yann/资产增长计划/`（所有命令都在这里执行，Python 用 `.venv/bin/python`）。

## 0. 开工前必读

1. `工作日志.md`：最近的反馈和「下次要改」，本期必须照做。
2. `YouTube视频准则.md`：繁体中文、标题规则、时长、字幕、画面、合规。
3. `pipeline/` 的脚本和 `videos/EP001_*`（成品结构参考）。
4. 查额度：`vidiq_balance`；MiniMax、Abo 能否正常调用（先跑一句短配音、一张小图试试）。任何一个不可用就停下并报告，不要硬做出残缺的视频。

## 1. 决定今天做什么（按优先级）

用 `ArtifactData` 读选题看板 https://claude.ai/artifact/94yFuzpcBPWDoVWWdAbdCf 的 `topics` 集合。

1. **有没做完的**：状态是「製作中」且对应的 `videos/EPxxx_*` 还没有成片或没上传 → 先把它做完发掉，今天就发这一支。
2. **频道主指定的**：状态是「已選定」的选题。有多个时，挑时效截止日最近的；都没有截止日就挑分数最高的。频道主会在看板上点选，或在对话里告诉 Claude，由 Claude 改成「已選定」。
3. **频道主没指定**：自己挑。
   - 从状态为「候選」的选题里选，优先顺序：截止日在 7 天内的时事题 > 延续最近一期的系列（例如读书系列《致富心態》的下一篇）> 分数最高的常青题。
   - 和最近 3 期不要撞题，同一类别不要连发 3 天。
   - 「候選」少于 3 个，或最高分低于 55 → 先按 `.claude/skills/topic-research/SKILL.md` 跑一次选题研究，再挑。选题必须来自 `选题关键词.md` 的方向。
   - 不做「放棄」的选题；不做需要荐股、承诺收益的选题。

选定后把状态改成「製作中」（带 `if_version`），新建 `videos/EPxxx_<繁體標題>/`，编号接着最大的往下排。

## 2. 制作

按准则和 EP001 的文件夹结构完成：文案（含一手资料核实，存 `99_工作文件/sources`）→ 配音 `pipeline/tts_episode.py` → 画面（先找可商用的网络图片 `pipeline/web_images.py`，找不到再用 `pipeline/images_episode.py` 生成，统一电影剧照风格）→ 图表与文字卡 `pipeline/graphics.py` → 合成 `pipeline/assemble.py` → 封面 `cover.py` → `07_发布信息`（标题、描述、标签、章节、upload.json）。

不停下来等频道主确认，用自动检查代替：

- 数字、引述、日期对照一手资料；查不到出处的内容删掉。
- 用 `pronounce_text` 检查数字和专有名词读音。
- 抽查至少 5 段字幕与语音的时间差，超过 0.2 秒要修正后重新出片。
- 抽帧检查：字幕不和画面文字重叠、没有错字、封面文字清楚。

## 3. 上传与定时公开

- 公开时间 = 今天台湾时间 20:00，即 `<今天日期>T20:00:00+08:00`。
- 命令：`.venv/bin/python upload.py <成片> --title ... --description-file ... --tags-file ... --thumbnail ... --language zh-Hant --privacy private --publish-at <公开时间> --ai-generated`
- 上传后用 YouTube API（`videos.list`，part=status）确认 `privacyStatus` 是 private 且 `publishAt` 已设定。**第一次使用定时公开时要特别确认**：如果 API 项目未通过审核，YouTube 可能把视频锁成私享，此时在报告里明确告诉频道主，并说明需要去 Studio 手动公开或申请 API 审核。
- 以下情况**不设定时公开**，只私享上传，并在报告里说明原因，让频道主决定：
  - 自动检查有没修好的问题（事实无法核实、字幕不同步、画面错误）。
  - 完成时已经晚于台湾时间 19:30（日本时间 20:30）。
  - 选题涉及敏感内容、可能违反准则「内容合规」。
- 不改动任何已上传视频（包括 EP001）的公开状态。

## 4. 收尾

1. 看板：状态改成「已發布」，`episode` 写上编号（带 `if_version`）。若没设定时公开，状态保持「製作中」，在 `risks` 写明原因。
2. `工作日志.md` 当天段落：做了哪一期、选题怎么来的（指定 / 自选及理由）、视频 ID 与 Studio 链接、公开时间、检查结果、遇到的问题。
3. 提交并推送到 GitHub（先检查没有密钥文件和密钥字符串）。

## 输出给频道主

简短报告：今天的标题、选题来源（你指定的 / 我自选的及理由）、Studio 链接、几点公开、自动检查结果、需要你处理的事（如有）。
